# KeePass port evaluation

Go's private fields and constructors separate validated passwords, Unix socket paths, and authorized browser sessions from raw input. Secret types redact their formatting and serialization and expose dedicated sinks for child stdin and private runtime files. The command builder rejects a secret as an argv element and provides a separate sudo path without payload stdin. The staged transaction has no commit method. A successful swap yields the handle that can run readiness checks and commit or roll back. Compile-fail tests cover these constraints, and the exhaustive analyzer checks outcome switches.

Go permits zero values and copied handles. Runtime guards still enforce transaction consumption and protect against reuse of a pre-transition handle. Clearing owned buffers reduces the lifetime of secret data. Copies inside the Go runtime, kernel, JSON parsing, Python setup, and KeePassXC have their own lifetimes. Filesystem races, service state, socket peer identity, and rollback across process boundaries still require behavior tests.

The production Go sources total about 6,000 lines, with about 1,700 additional lines of Go tests. The stripped Linux amd64 builds measured with Go 1.27.4, `CGO_ENABLED=0`, `-trimpath`, and `-ldflags='-s -w'` were 3,870,880 bytes for `nas-keepass-setup`, 7,827,616 bytes for `nas-secrets`, and 7,418,016 bytes for `nas-unlock-api`. These measurements cover standalone Go executables. The Nix wrappers and dependency closures are additional.


## Refinements after the Go and Zig comparison

Root activation uses descriptor-relative filesystem calls through `golang.org/x/sys/unix` and confines recursive removals to an `os.Root` opened from the parent descriptor. Tree renames require `RENAME_NOREPLACE`. The KDBX move-aside uses the same flag and reports the coordinated hard-link fallback if the kernel or filesystem returns `EINVAL` or `ENOSYS`. Rollback preserves the previous tree and exits 125 when removing the live root fails. The browser timeout test runs through the real operation coordinator and observes a completed rollback before identity recovery starts.

All three Go entry points set `PR_SET_DUMPABLE=0` and set both core limits to zero. Secret buffers use ordinary Go memory and remain eligible for swap. Go's runtime and standard library can copy buffers onto pages shared with other allocations, so the port uses neither page locking nor per-page dump advice. These startup controls cover the Go process. Exec may reset dumpability in external tools, and the hard core limit is inherited. Compile-fail tests cover the setup-mode link boundary, password operands, environment assignments, and terminal transaction states. Generic JSON encoders accept any Go value, so tests verify that direct and nested serialization hides secret bytes.

`nas-secrets` uses KeePassXC and systemd, plus sudo and coreutils for its unprivileged console path. The wrapper uses Bash to set the package paths and exec the binary. The activation PATH has no jq, OpenSSL, Python, libargon2, htpasswd, grep, sed, findutils, or util-linux dependency. The existing Python operation coordinator remains an external appliance command. The separate setup helper uses util-linux for `runuser` when root launches KeePassXC as the database owner.
